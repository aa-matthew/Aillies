# Decisions

Current-policy navigation: decisions 43–44 supersede earlier reopen scope and the two-second preparation cutoff; decision 45 supersedes logical-turn no-replay wording; decisions 46–47 define provider-first desktop controls and eight-digit pairing. Earlier entries remain historical rationale. Use [current architecture](ARCHITECTURE.md) and [handoff](HANDOFF-CODEX.md) for operative behavior.

Short log of choices that shape the code. Newest last. Add one line of context and the consequence.

1. **Name: Aillies** (2026-10-10). Picked over “Ailliance”: shorter, matches the project name, reads as “allies”. Bundle id `is.anyax.aillies`. Logo: two overlapping rings, with the shared lens highlighted.
2. **Rust core + Tauri 2 shell.** One codebase for macOS, Windows and Ubuntu. Security behavior lives only in the Rust crates; the shells are thin.
3. **Identity = certificate fingerprint; pinned mutual TLS 1.3.** Replaces Peer Route’s shared pairing key: every device has its own identity, so revocation is per device and immediate.
4. **Invite code + verification code.** The invite carries B’s fingerprint (so A can’t be pointed at an impostor) and a one-time secret; the three-part code binds both fingerprints and the secret for a human comparison. Approval is required on both sides.
5. **No retries anywhere.** The executor never retries; Aillies writes `request_max_retries = 0` and `stream_max_retries = 0` into the Codex provider so Codex doesn’t replay either. Failures that may have reached OpenAI are labeled *delivery uncertain*.
6. **Tool allowlist follows real Codex.** codex-cli 0.162.1 sends `function`, `custom`, `tool_search` and `web_search` tools. All are allowed, plus `image_generation` and `local_shell`; anything else (for example remote `mcp`) is refused.
7. **New ports 18522 (loopback) and 18544 (peer)** so Aillies can run next to the legacy Peer Route (18322/18444) during migration.
8. **Alpha secrets in 0600 files.** Faster to ship; moving to OS credential stores is milestone M7.
9. **Plain HTML/JS window, no build step.** Matches the “small static UI” direction; contributors don’t need Node to build the app. Move to TypeScript once the UI grows.
10. **Upstream override only to loopback.** `AILLIES_CODEX_UPSTREAM` accepts `http://127.0.0.1:` or `http://localhost:` targets, so tests can run without a stray variable ever sending tokens elsewhere.
11. **AGENTS.md is the single agent guide** (2026-10-11). `CLAUDE.md` only imports it, so Claude, Codex and other agents follow the same rules. Feature locations live in `docs/FEATURES.md`.
12. **Restore removes only Aillies’ lines** (alpha.3). The Codex app edits `config.toml` itself (trusted projects, notices), so a byte-for-byte guard blocked real users. `merge_restore` reverses Aillies’ edits structurally and still refuses when it can’t parse.
13. **Windows builds use the GNU target** when cross-building from Linux (Ubuntu Rust + `-Zbuild-std` + mingw + NSIS); CI builds MSVC on Windows runners. See `scripts/build-windows-from-linux.sh`.
14. **Upstream override is parsed, not prefix-matched** (2026-10-11, review finding 1). `upstream_override` parses the URL and accepts only `http`, a loopback host (`127.0.0.0/8`, `::1`, `localhost`), an explicit non-default port, no user info and no fragment. Before this, `http://127.0.0.1:80@example.com/…` passed while targeting `example.com`.
15. **Stream completion means a real SSE terminal event** (2026-10-11, review finding 2). `TerminalScanner` parses SSE framing incrementally (any chunking, `\n` or `\r\n`, comments ignored, dispatch on a blank line). It counts `response.completed|failed|incomplete` only from the `event:` field or the payload’s top-level `type`. Lines are capped at 4 KiB, so huge payloads aren’t buffered; a truncated payload is read only if it starts with `{"type":"…"`. An event without its terminating blank line isn’t dispatched, so a cut stream is reported as *delivery uncertain*.
16. **Desktop crate stays outside the Cargo workspace, but `make test`/`make lint` cover it** (2026-10-11, review finding 3). It pulls WebKitGTK/WebView system libraries and has its own lockfile, so `cargo test --workspace` stays portable. `make test` = `test-core` + `test-desktop`; `make lint` also runs desktop fmt and clippy plus a UI JS syntax check; CI runs the same per OS.
17. **Model choice.** Install keeps the user’s existing root `model`; it writes `gpt-5.5` only when none is set, unless `--model` is given.
18. **Codex client identity.** Upstream requests send `originator: codex_cli_rs`, `User-Agent: codex_cli_rs/0.159.0` and `version: 0.159.0`, carried over from Peer Route. The real Codex is newer (0.162.1); revisit if the backend starts checking versions. *Unverified against the live backend.*
19. **No system proxy for upstream.** The executor ignores `HTTPS_PROXY` (`no_proxy()`, as in Peer Route) so tokens never go through an intermediary. Sharing devices that require a proxy can’t reach OpenAI. This is a known limitation.
20. **Invites list every non-loopback IPv4 address plus `<hostname>.local`** (and `127.0.0.1` only with `AILLIES_ADVERTISE_LOOPBACK`). Whoever holds the code learns these LAN addresses. Accepted because the code is private and single-use.
21. **Convenience defaults.** Creating an invite turns sharing on. The first successful pairing selects the new device if the destination was *This device*.
22. **Pause blocks every destination**, including *This device* (fail closed; Codex shows `routing_paused`).
23. **Gray for “This device”.** Following the spec, green means routing through a paired device, gray means paused or using this device, orange means action required.
24. **Desktop lifecycle.** Node, then tray, then the window on demand. Closing the window hides it; Quit stops the node. The second instance hands off to the first via `tauri-plugin-single-instance`.
25. **Windows installer** is per-user (no admin) and fetches WebView2 with the download bootstrapper (embedding it was blocked in the build environment).


26. **Parse values, preserve formatting during restore** (2026-10-11). Use `toml` 0.8 to validate full files and recognize `model_provider` semantically (single quotes, tabs and comments are valid). Continue editing statements rather than reserializing the file. Invalid or ambiguous TOML refuses without changing either file or receipt. Removing a selected peer leaves its destination selected but unavailable: only an explicit selection can choose the local account.
27. **Fast requires two choices** (2026-10-11). B owns `allow_fast_mode`, default false. A owns an optional preference per destination, also default false. Peer status advertises permission using a backwards-compatible, default-false field. A sends `service_tier: priority` when enabled, `default` otherwise, so a saved Codex Fast setting cannot override Aillies' switch. B enforces permission even on hand-crafted peer requests. Revocation rejects subsequent Fast requests; it never silently downgrades or resends. Permission requests Fast; it cannot grant a backend entitlement or prove a billing rate.
28. **Explicit image MCP adapter for custom-provider Codex** (2026-10-11). The provider stays `requires_openai_auth = false`; A never needs B's login. The integration also installs a Streamable HTTP MCP server at authenticated loopback `/mcp/images`, using the existing local Codex key. `generate_image` submits one ordinary Responses request with the hosted image tool through the same routing, approval and tier path. It uses the root Codex model setting (existing default only if absent); profile/CLI model overrides are not available to this tool. Only creation is exposed. Collect at most 64 MiB of SSE within 890 seconds, require a terminal event, read the final image from `output_item.done` or completed output, validate base64 and PNG signature, and write a private local artifact. No upstream body or model text appears in failures or logs. A live Windows B response delivered the image in `output_item.done` and an empty completed output list. The receipt owns only the MCP table it installed; older receipts never remove a later user-added MCP table. Existing installations need integration off/on and a new Codex process/chat to discover the tool.
29. **Verification commands must fail on failed assertions** (2026-10-11). Shell `&& echo` assertions in the smoke script could allow failures to fall through to success under `set -e`; assertions now run separately. The UI syntax target now also fails when Node is absent instead of claiming a skip after a syntax error.

30. **Desktop log events cannot carry error payloads** (2026-10-11). Replace arbitrary log strings with `LifecycleEvent`; only fixed messages, the public build version and a numeric loopback port can be written. Panic hooks record a fixed event, never `PanicHookInfo`, which could contain input-derived text. Unit coverage captures every event and checks the allowed output contract.
31. **Respect Codex's tool approval policy** (2026-10-11). Integration does not grant blanket or per-tool approval. Real codex-cli 0.161.0 required a trusted workspace to discover the MCP tool; `approval_policy = never` refused its mutating call until the isolated test configuration explicitly approved that single tool. With that test-only approval, the real CLI generated and saved a PNG through Windows B. Normal interactive users approve the image tool in Codex if asked. See the [official configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference) for `mcp_servers.<id>.tools.<tool>.approval_mode`.

## 42. Explicit quit, switch and reopen on macOS (2026-10-11)

Aillies offers **Quit, switch & reopen** after an existing-chat provider change is blocked by an open Codex process. Review is read-only and shows the owning apps and terminal count before the user acts. Process plans are in memory, expire after two minutes, are single-use, and are invalidated by other provider changes. Changed process identity/inventory refuses before closing anything. Aillies runs the orchestration itself on a background worker, independent of the Codex app it closes.

Only current-user Codex processes and known owning applications (ChatGPT/Codex, VS Code, Cursor, Windsurf) are eligible. Terminal Codex must have an identifiable working directory and a lock in the configured Codex home; unknown/background clients and other-user clients refuse before any close. App quit uses normal Apple events so unsaved-editor dialogs can stop the flow; terminal clients and the known shared daemon receive SIGTERM once. No SIGKILL/force quit is used on clients. The user must finish active work first; automatic idle detection across direct-provider sessions is unavailable. Helper commands and shutdown waits are bounded.

The existing global process guard and transactional migration stay in place. No history/config edit occurs unless all Codex processes have exited; new/respawning clients refuse. Ordinary failure reopens clients that exited, while a failed migration with a recovery journal keeps them closed for repair. Successful-switch/reopen failure is reported separately. GUI apps reopen normally; terminal clients reopen in macOS Terminal at their original working directory, configured home and executable, with `codex resume --all`. This opens a picker, not an automatic turn or exact-session selection. Original command lines, prompts, environment variables, approval-bypass flags and pending actions are never captured or replayed. Process paths are transient and excluded from diagnostics. Windows/Linux retain manual quit/reopen until platform-specific shutdown/resume can be verified.

## 45. User-authorized bounded retries and recent warnings (2026-10-11)

The user explicitly requested three retries and confirmed replay after OpenAI errors or interrupted responses, accepting possible duplicate work/usage. This supersedes decision 5 and later no-retry statements for requester routing only. Execute the initial attempt plus at most three retries, with 500 ms, 1 s and 2 s backoff and an 880-second total logical-turn budget. Retry upstream rejections (including HTTP 400), unexpected formats, failed/incomplete/cut streams, unreachable peers/upstreams and busy refusals. Local validation, login/authorization, sharing/tier/version and route-change refusals stop. Keep the exact destination snapshot, model, history, tier and session hint; current pause/removal/selection is checked before further attempts.

The requesting node owns the budget; the executor and peer server remain one-send per attempt and Codex retries remain zero. Buffer each attempt in memory up to 64 MiB until a real successful SSE terminal event, emit only fixed SSE keepalive comments while waiting, discard failed partial content, and return one winning attempt. After stream headers have been sent, exhausted retries yield a fixed response.failed SSE event; failures before stream headers retain their HTTP envelope. Cancellation drops the future and upstream stream, including backoff, and never starts another attempt. Forced image MCP requests require a fully decoded PNG before winning; only the winner is saved. No atomic generation guarantee is implied: earlier requests may still run upstream.

Local execution captures the initial account as an expected account. Sharing nodes bind client fingerprint + generated trace to the first executor/account in a bounded in-memory 1,024-entry, 15-minute map. A first potentially sent attempt is distinguished from confirmed pre-send/busy refusals so recovery can establish its first binding later. A retry cannot recreate a missing binding after a sharing-node restart or expiry. Peer readiness advertises supports_pinned_retries, default false for old nodes; a reachable old/incompatible peer stops further execution. No account IDs, credentials, raw headers or content cross this metadata path.

Add bounded numeric attempt identifiers to request observations and fixed retry numbers to warning entries; trace + attempt distinguishes upstream and hosted attempts. Keep one requester incoming logical turn and the latest-100 rings. Home reads the latest four failure/retry notices newest first, derives messages from FailureCode/status only, escapes all strings, and retains history across success/dismiss/restart. This is an in-app list, without repeated OS popups or uploads.

## 47. Eight-digit nearby pairing and authenticated secret exchange (2026-10-11)

The user requested eight random numbers and a handshake that exchanges the pairing token afterwards. Generate eight uniform cryptographically random decimal digits, preserving leading zeroes. Eight digits cannot encode the full address/fingerprint/secret invite; use local mDNS discovery only while a numeric code is active, advertising public connection metadata under a random service name. Do not advertise a code hash or password verifier. No central rendezvous or internet short-code service is introduced; retain full codes for Tailscale/private networks and old devices.

Use SPAKE2 over existing mutual TLS, with domain-separated roles and both certificate fingerprints bound into the exchange. Derive the AES-256-GCM key from the PAKE result and encrypt/authenticate the existing full invite with fingerprint-bound AAD. Send the recovered random 32-byte one-time secret through the existing pinned `/v1/pair` path; require the same bootstrap requester certificate, matching verification codes and approval on both devices. Stored certificate authorization remains the durable access mechanism. OpenAI OAuth tokens never cross this path. No security audit is claimed for this implementation or its SPAKE2 dependency.

Limit each active code to ten minutes and five PAKE executions, including malformed active PAKE messages. The fifth response may complete; later guesses refuse. Consumption, replacement, sharing off, shutdown and expiry remove numeric discovery. Searches are serialized, bounded to 25 seconds / 16 candidates / four concurrent probes and fail on ambiguous matches. No retries are added to pairing. Default CLI and desktop show grouped digits; full-code entry/generation remain secondary. macOS declares its local-network purpose and Bonjour service. Physical cross-device permission/firewall acceptance remains required.
