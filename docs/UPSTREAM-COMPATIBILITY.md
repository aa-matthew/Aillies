# Current build: router-core-v4-pairing (1.0.0)

The user explicitly requested 9router core alignment. This build supersedes router-core-v3.

- New Windows and Apple Silicon installers use originator `codex_cli_rs`, User-Agent `codex_cli_rs/0.159.0`, and version `0.159.0`, matching the pinned reference.
- Default instruction text is copied as data from the reference under its MIT license. Explicit instructions remain intact. Existing developer instructions from a normalized peer prefix are not duplicated.
- Supported `[1m]`/review aliases and effort suffixes resolve to their upstream model names. Lite none/minimal becomes low; ultra maps according to the reference model capabilities. Unknown model IDs are not guessed.
- Nested function declarations become flat Responses tools. Unsupported Unicode-property regex constraints are removed; ordinary patterns and property names remain. Namespaced function tools receive recursive allowlist and size validation.
- Top-level client-only options are filtered using the same allowlist approach as 9router. Null server references are removed; non-null history references and unsupported tools still fail closed. Duplicate tool prefixes are validated and counted as their effective deduplicated set for ordinary requests. This fixes two reproduced validator mismatches; it does not prove the exact cause of the reported 5.6 failure.
- Capture bounded session hints before normalization. Codex session headers, then x-client-request-id, precede body cache/session/conversation/metadata hints. A pinned peer receives only the bounded hint plus a generated trace UUID in dedicated headers. An explicit body prompt_cache_key is preserved independently of the upstream session_id. Without a hint, cache a UUID+timestamp identity by account-scoped digest of the first 50 assistant UTF-16 units, then account scope. Only digests and generated IDs are retained. Caps are 5,000 assistant / 1,000 account entries with two-hour idle expiry; per-turn outgoing request IDs stay unique.
- Existing Lite/ordinary selection, backend tier formatting and encrypted-reasoning includes remain; include fields and hosted-image behavior are preserved.

## Explicit differences retained

Account/model fallback, account rotation, token refresh, raw upstream errors, remote image fetching and new hosted tool permissions remain excluded. Requester retries are now explicitly authorized and bounded by decision 45; executors and peers still send each attempt once. These preserve Aillies' repository invariants and supported API boundary. Aillies is not a complete 9router port. In particular, OAuth refresh to auth.openai.com would need a separate credential-policy change; the owning device's Codex still refreshes its login.

## Session scope and intentional differences

The Codex path is covered. Claude Code and Antigravity envelopes, workspace-ID fallback, continuation IDs, account rotation and OAuth refresh are not ported. Session values must additionally be printable ASCII to fit the peer/header contract. Expiry is checked on lookup rather than a thirty-minute cleanup interval. Generated IDs reset on restart, as in 9router. An identity does not hold server-side history: every turn still carries full input.

## Diagnostics, provider switching and images

Exports contain three independent bounded lists: latest 100 incoming turns, latest 100 actual upstream attempts on this device, and latest 100 failures/warnings. Phase, local HTTP status, upstream HTTP status, elapsed/first-byte times, closed validation category and a generated cross-device trace UUID replace raw body logging. Export on both devices to inspect both sides; no remote log-reading API is added. Old failure journals remain readable. Startup marks unfinished observations delivery_uncertain, without replay.

Switching an existing chat requires quitting Codex. Aillies stages indexed and valid unique unindexed normal-provider sessions (including archived ones), updates session metadata plus state_5.sqlite, and adjusts byte offsets in thread_history_1.sqlite when present. Original transcript records after the first metadata line are copied unchanged. When needed, the latest thread_settings_applied event is appended with only the provider ID and next ordinal changed, so index rebuilding resumes with the selected provider; all other chat settings and permissions are retained. File-only legacy homes are supported without inventing database rows. A private recovery journal coordinates files, config receipt and both SQLite databases; recovery writes absolute offsets so a crash cannot shift them twice. File-only changes use a durable journal completion flag; mixed/indexed changes use the provider index as the commit marker. Unknown history versions, external/symlink paths, conflicting IDs and malformed/unsupported records refuse the switch. Since alpha.9, preparation runs on a background worker without a production time cutoff; the UI shows phases and counts. Optional test-only deadlines exercise refusal/cleanup. Process guards, bounded records and transactional recovery remain. Other custom-provider chats are left alone. The opposite direction restores all Aillies chats to the root provider saved in the config receipt; this does not preserve a separate provider choice for each old chat. Profiles with provider overrides remain outside the root-provider switch.

Installed codex-cli 0.161.0 was checked with an isolated synthetic home: list, resume and read work after both directions, including paginated history. An app-server resume override alone did not persist the provider for the next process, so it is not used as the migration mechanism. The running desktop application's memory must be released by quitting/reopening as the user accepted.

Image MCP calls can pass the active model explicitly; omission uses the saved root model. Image creation uses ordinary Responses and the same selected destination, permission checks and bounded requester retry policy. Completed results must fully decode as bounded PNGs. The result includes an absolute local Markdown image reference and instructions to display it in the final reply; showing an existing image should reuse its saved path. This guidance does not guarantee model compliance or resolve unrelated upstream rejection. Tests use a complete PNG across two pinned nodes. Fresh live acceptance of 5.6 Sol, approval review and image generation remains to be checked after installing both updated devices; approvals are never bypassed.
